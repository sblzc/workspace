feat: mount the hosted GitHub MCP connector (zero code)

The remote endpoint https://api.githubcopilot.com/mcp speaks Streamable HTTP
and takes a plain PAT as a bearer token, which sidesteps the two things this
sandbox breaks: stdio transport (needs piped subprocesses) and every
credential helper (spawns sh.exe). So the connector is a config entry, not
code.

Verified end to end:
  initialize                -> 200  github-mcp-server/remote-b1364158
  notifications/initialized -> 202
  tools/list                -> 200, 46 tools
  mcp__github__get_me       -> {"login":"sblzc","id":175811836}

The token is NOT stored in cordis.patch.yml. An !!js expression reads it at
load time from D:/radio/.github-token, so the profile file stays safe to back
up or share. process.env was the preferred source, but setx fails in this
sandbox with "Access to the registry path is denied", and a running dsh would
not see a newly set user variable anyway.

The expression throws when the token is missing rather than yielding an empty
bearer token, which would still pass the z.dict(String) schema and surface
later as an opaque 401.

Also adds AGENTS.md (project conventions) and docs/github-connector.md.
